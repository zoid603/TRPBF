# Game Achievement Tracker

Приложение для каталога игр, достижений и прогресса игроков. Консольная
версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

## Назначение

Game Achievement Tracker позволяет вести каталог игр, список достижений
и фиксировать прогресс игроков по достижениям. В ПР5 консольное приложение
переведено на начальный этап веб-разработки: данные предметной области
отображаются в браузере через view-функции Django.

Приложение позволяет:

* просматривать список игр и количество достижений в браузере;
* просматривать достижения выбранной игры;
* просматривать общий список достижений;
* просматривать информацию о конкретном достижении;
* просматривать список записей прогресса;
* просматривать карточку прогресса игрока;
* добавлять игры, достижения и игроков (консольная версия);
* фиксировать и обновлять прогресс (консольная версия);
* хранить данные между запусками приложения.

## Целевая аудитория

Игроки, которые хотят вести каталог игр и отслеживать прогресс получения
внутриигровых достижений.

## Предметная область

Основными объектами предметной области являются:

* игра;
* достижение;
* игрок (пользователь);
* прогресс.

Игрок выполняет действия в игре и продвигается к получению достижения.
Прогресс связывает игрока и достижение и хранит количество выполненных
действий, по которому рассчитываются процент выполнения и статус.

## Основные сущности

### Game – игра

Объект `Game` представляет игру каталога.

Основные атрибуты:

* `id` – уникальный идентификатор игры;
* `title` – название игры.

Основные методы:

* `__str__()` – строковое представление игры.

### Achievement – достижение

Объект `Achievement` представляет внутриигровое достижение, связанное
с игрой.

Основные атрибуты:

* `id` – уникальный идентификатор достижения;
* `game` – объект `Game`;
* `name` – название достижения;
* `required_actions` – количество действий для получения;
* `is_secret` – признак секретного достижения.

Основные методы:

* `is_unlocked()` – проверка, получено ли достижение;
* `progress_percent()` – расчет процента выполнения;
* `__str__()` – строковое представление достижения.

### User – игрок

Объект `User` представляет профиль игрока.

Основные атрибуты:

* `id` – уникальный идентификатор игрока;
* `username` – имя игрока.

Основные методы:

* `from_data()` – создание объекта из записи JSON;
* `__str__()` – строковое представление игрока.

### Progress – прогресс

Объект `Progress` представляет прогресс игрока по конкретному достижению.

Основные атрибуты:

* `id` – уникальный идентификатор записи прогресса;
* `user` – объект `User`;
* `achievement` – объект `Achievement`;
* `completed_actions` – количество выполненных действий;
* `record_date` – дата фиксации прогресса.

Основные методы:

* `update()` – обновление действий и даты;
* `percent()` – процент выполнения достижения;
* `status()` – текстовый статус прогресса;
* `__str__()` – строковое представление прогресса.

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/games/` – список игр: объекты `Game` из `data/games.json`
  (view-функция `games()`);
* `/games/<int:game_id>/` – страница игры и её достижений
  (view-функция `game_detail()`);
* `/achievements/` – список всех достижений
  (view-функция `achievements()`);
* `/achievements/<int:achievement_id>/` – страница достижения
  (view-функция `achievement_detail()`);
* `/progress/` – список записей прогресса из `data/progress.json`
  (view-функция `progress_list()`);
* `/progress/<int:progress_id>/` – карточка прогресса
  (view-функция `progress_detail()`);
* любой несуществующий адрес – кастомная страница ошибки 404
  (обработчик `page_not_found()`).

На страницах деталей кнопки перехода убраны: те же адреса доступны из
навигационной панели (Главная, Игры, Достижения, Прогресс), поэтому
дублировать их в карточке не требуется.

Сами объекты в списках кликабельны: игры в списке `/games/` ведут на
страницу игры `/games/<id>/`, достижения в списках `/games/<id>/` и
`/achievements/` ведут на страницу достижения
`/achievements/<id>/`. На странице достижения название игры является
ссылкой на страницу этой игры.

Если игра, достижение или запись прогресса с указанным идентификатором
не найдена, соответствующая view-функция возвращает код статуса 404 и
страницу с пояснением.

### Обработка ошибки 404

За обработку несуществующих адресов отвечает параметр `handler404`,
объявленный в корневом `config/urls.py` и указывающий на
`homepage.views.page_not_found`. Обработчик принимает `request` и
`exception` и возвращает HTML-страницу с кодом статуса 404. Шаблон страницы
хранится в `homepage/templates/404.html` и оформлен через Bootstrap 5.3.

`handler404` срабатывает автоматически, когда адрес не совпал ни с одним
маршрутом из `urlpatterns`. Отдельно каждый view сам решает, когда объект
считается не найденным, и возвращает ответ с кодом 404. Кастомная страница
404 отображается при `DEBUG = False`; при `DEBUG = True` Django показывает
техническую страницу отладки.

Содержимое страницы 404 зависит от запрошенного адреса: если в разделе
`/games/`, `/achievements/` или `/progress/` передан нецелочисленный
идентификатор (например, `/games/шфцвцфтзв`), выводится подсказка вида
«ID игры должен быть целым числом». Для остальных адресов показывается
общее сообщение. Текст подбирает функция `_not_found_message()` в
`homepage/views.py`, а шаблон `homepage/templates/404.html` выводит его
через переменную контекста.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка игр;
* просмотр достижений выбранной игры;
* просмотр списка достижений;
* просмотр информации о достижении;

* просмотр карточки прогресса.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе
они появятся после добавления форм и POST-запросов:

* добавление игры;
* добавление достижения;
* поиск достижения по названию;
* создание игрока;
* запись и обновление прогресса.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/games.json`;
* `data/users.json`;
* `data/achievements.json`;
* `data/progress.json`.

При загрузке данные из JSON преобразуются в объекты `Game`, `User`,
`Achievement` и `Progress`. При сохранении объекты преобразуются обратно
в JSON. Для связи прогресса с игроком и достижением используются
идентификаторы `user_id` и `achievement_id`, для связи достижения с игрой –
идентификатор `game_id`.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за запуск
консольного приложения, отображение меню и пользовательские сценарии.

### `config/`

Пакет настроек Django-проекта:

* `settings.py` – настройки проекта и подключение приложений;
* `urls.py` – маршрутизация верхнего уровня;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу и общий каркас страниц:

* `views.py` – функция `page()` (общий HTML-каркас с Bootstrap),
  view-функция `index()` и обработчик `page_not_found()`;
* `urls.py` – маршрут главной страницы;
* `templates/404.html` – шаблон кастомной страницы ошибки 404.

Функция `page()` размещена здесь, потому что главная страница задаёт общий
вид всех остальных страниц. Остальные приложения импортируют её.

### `games_app/`

Django-приложение, отвечающее за игры:

* `views.py` – view-функции `games()` и `game_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `achievement/`

Django-приложение, отвечающее за достижения:

* `views.py` – view-функции `achievements()` и `achievement_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `progress_records/`

Django-приложение, отвечающее за прогресс игроков:

* `views.py` – view-функции `progress_list()` и `progress_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

Примечание. Имена Django-приложений (`games_app`, `achievement`,
`progress_records`) отличаются от одноимённых модулей ПР3 (`games.py`,
`achievements.py`, `progress.py`), чтобы не перекрывать их при импорте:
пакет приложения с тем же именем занял бы место модуля в `sys.path`, и
консольная версия и тесты перестали бы импортировать функции ПР3. Именно
поэтому приложение игр называется `games_app`, а не `games` – каталог
`games/` перекрыл бы модуль `games.py`.

### `models/`

Классы предметной области (пакет ПР3):

* `games.py` – класс `Game`;
* `achievements.py` – класс `Achievement`;
* `users.py` – класс `User`;
* `progress.py` – класс `Progress`.

### `games.py`, `achievements.py`, `users.py`, `progress.py`

Функции бизнес-логики ПР3: добавление и поиск игр, достижений и игроков,
запись и обновление прогресса, поиск прогресса по идентификатору
(`get_progress_by_id()`, добавлена в ПР5).

### `storage.py`

Загрузка и сохранение данных:

* JSON → объекты Python;
* объекты Python → JSON.

### `utils.py`

Вспомогательные функции консольного ввода:

* `input_int()` – безопасный ввод целого числа;
* `input_date()` – безопасный ввод даты.

### `tests/`

Автоматизированные тесты проекта (pytest).
