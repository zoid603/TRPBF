# Game Achievement Tracker

Приложение для каталога игр, достижений и прогресса игроков. Консольная
версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5), который
в ПР6 переведён на систему шаблонов Django.

## Назначение

Game Achievement Tracker позволяет вести каталог игр, список достижений
и фиксировать прогресс игроков по достижениям. В ПР6 веб-часть переведена
с формирования HTML-кода в Python-функциях на стандартную для Django схему
`View → Context → Template → HTML`: данные предметной области передаются
в шаблоны через контекст и отображаются в браузере.

Приложение позволяет:

* просматривать список игр и количество достижений в браузере;
* просматривать достижения выбранной игры;
* просматривать общий список достижений;
* просматривать информацию о конкретном достижении;
* просматривать список записей прогресса;
* просматривать карточку прогресса игрока;
* добавлять игры, достижения и игроков (консольная версия);
* фиксировать и обновлять прогресс (консольная версия);
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;

* Django Template Language (DTL) – шаблоны страниц;

## Целевая аудитория

Игроки, которые хотят вести каталог игр и отслеживать прогресс получения
внутриигровых достижений.

## Предметная область

Основными объектами предметной области являются:

* игра;
* достижение;
* игрок (пользователь);
* прогресс.

Игрок выполняет действия в игре и продвигается к получению достижения.
Прогресс связывает игрока и достижение и хранит количество выполненных
действий, по которому рассчитываются процент выполнения и статус.

## Основные сущности

### Game – игра

Объект `Game` представляет игру каталога.

Основные атрибуты:

* `id` – уникальный идентификатор игры;
* `title` – название игры.

Основные методы:

* `__str__()` – строковое представление игры.

### Achievement – достижение

Объект `Achievement` представляет внутриигровое достижение, связанное
с игрой.

Основные атрибуты:

* `id` – уникальный идентификатор достижения;
* `game` – объект `Game`;
* `name` – название достижения;
* `required_actions` – количество действий для получения;
* `is_secret` – признак секретного достижения.

Основные методы:

* `is_unlocked()` – проверка, получено ли достижение;
* `progress_percent()` – расчет процента выполнения;
* `__str__()` – строковое представление достижения.

### User – игрок

Объект `User` представляет профиль игрока.

Основные атрибуты:

* `id` – уникальный идентификатор игрока;
* `username` – имя игрока.

Основные методы:

* `from_data()` – создание объекта из записи JSON;
* `__str__()` – строковое представление игрока.

### Progress – прогресс

Объект `Progress` представляет прогресс игрока по конкретному достижению.

Основные атрибуты:

* `id` – уникальный идентификатор записи прогресса;
* `user` – объект `User`;
* `achievement` – объект `Achievement`;
* `completed_actions` – количество выполненных действий;
* `record_date` – дата фиксации прогресса.

Основные методы:

* `update()` – обновление действий и даты;
* `percent()` – процент выполнения достижения;
* `status()` – текстовый статус прогресса;
* `__str__()` – строковое представление прогресса.

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`, шаблон `homepage/index.html`);
* `/games/` – список игр: объекты `Game` из `data/games.json`
  (view-функция `games()`, шаблон `games_app/games.html`);
* `/games/<int:game_id>/` – страница игры и её достижений
  (view-функция `game_detail()`, шаблон `games_app/game_detail.html`);
* `/achievements/` – список всех достижений
  (view-функция `achievements()`, шаблон `achievement/achievements.html`);
* `/achievements/<int:achievement_id>/` – страница достижения
  (view-функция `achievement_detail()`,
  шаблон `achievement/achievement_detail.html`);
* `/progress/` – список записей прогресса из `data/progress.json`
  (view-функция `progress_list()`,
  шаблон `progress_records/progress_list.html`);
* `/progress/<int:progress_id>/` – карточка прогресса
  (view-функция `progress_detail()`,
  шаблон `progress_records/progress_detail.html`);
* любой несуществующий адрес – кастомная страница ошибки 404
  (обработчик `page_not_found()`, шаблон `homepage/templates/404.html`).

Для формирования страниц используются Django-шаблоны. Генерация HTML
непосредственно в Python-коде веб-представлений больше не используется,
а функция `page()`, собиравшая общий HTML-каркас в ПР5, удалена.

На страницах списков есть кнопка возврата на главную («← На главную»),
а на страницах деталей — кнопка возврата к соответствующему списку
(«← К списку игр», «← К списку достижений», «← К списку прогресса»).
Кроме этого, те же разделы всегда доступны из навигационной панели
(Главная, Игры, Достижения, Прогресс).

Сами объекты в списках кликабельны: игры в списке `/games/` ведут на
страницу игры `/games/<id>/`, достижения в списках `/games/<id>/` и
`/achievements/` ведут на страницу достижения
`/achievements/<id>/`. На странице достижения название игры является
ссылкой на страницу этой игры. Ссылки формируются через именованные
маршруты (`{% url %}`), а не жёстко заданные адреса.

Если игра, достижение или запись прогресса с указанным идентификатором
не найдена, соответствующая view-функция передаёт в шаблон `None`,
шаблон выводит страницу «Объект не найден», а ответ возвращается с
кодом статуса 404.

### Обработка ошибки 404

За обработку несуществующих адресов отвечает параметр `handler404`,
объявленный в корневом `config/urls.py` и указывающий на
`homepage.views.page_not_found`. Обработчик принимает `request` и
`exception` и возвращает HTML-страницу с кодом статуса 404. Шаблон страницы
хранится в `homepage/templates/404.html`, наследует `base.html` и выводит
контекстную подсказку.

`handler404` срабатывает автоматически, когда адрес не совпал ни с одним
маршрутом из `urlpatterns`. Отдельно каждый view сам решает, когда объект
считается не найденным, и возвращает ответ с кодом 404. Кастомная страница
404 отображается при `DEBUG = False`; при `DEBUG = True` Django показывает
техническую страницу отладки.

Содержимое страницы 404 зависит от запрошенного адреса: если в разделе
`/games/`, `/achievements/` или `/progress/` передан нецелочисленный
идентификатор (например, `/games/шфцвцфтзв`), выводится подсказка вида
«ID игры должен быть целым числом». Для остальных адресов показывается
общее сообщение. Текст подбирает функция `_not_found_message()` в
`homepage/views.py`, а шаблон `homepage/templates/404.html` выводит его
через переменную контекста.

## Django Template Language

Веб-интерфейс построен на Django Template Language (DTL). Представления
подготавливают данные и передают их в шаблоны через контекст, шаблоны
формируют HTML.

### Базовый шаблон и наследование

Общий каркас всех страниц вынесен в базовый шаблон `templates/base.html`:

* объявление HTML-документа, кодировка, подключение Bootstrap и
  собственного CSS;
* логотип, навигация и основной контейнер `{% block content %}`;
* подвал с текущим годом и подключение JavaScript.

Базовый шаблон содержит блоки, которые переопределяют дочерние страницы:

```django
{% block title %}Game Achievement Tracker{% endblock %}
{% block content %}{% endblock %}
```

Дочерние шаблоны используют наследование:

```django
{% extends "base.html" %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны и подключаются
через `{% include %}`:

* `templates/includes/navigation.html` – навигация, общая для всех
  страниц (подключается в `base.html`);
* `games_app/includes/game_card.html` – карточка игры в списке;
* `achievement/includes/achievement_card.html` – карточка достижения;
* `progress_records/includes/progress_status.html` – строка прогресса
  с бейджем статуса.

Пример подключения:

```django
{% include "games_app/includes/game_card.html" %}
```

### Циклы, условия и пустые коллекции

Списки выводятся циклами `{% for %}` с веткой `{% empty %}`, статусы и
признаки – условиями `{% if %}`:

```django
{% for achievement in game_achievements %}
    ...
{% empty %}
    <li>Для этой игры пока нет достижений.</li>
{% endfor %}
```

### Фильтры шаблонов

Применяются фильтры форматирования отображаемых данных:

* `|length` – количество элементов (например, «Всего игр: 4»);
* `|default:"Без названия"` – значение по умолчанию для пустых полей.

Пример:

```django
{{ game.title|default:"Без названия" }} ({{ games_list|length }})
```

### Именованные URL и пространства имён

В `urls.py` каждого приложения объявлен `app_name`, а маршруты имеют
параметр `name`. Ссылки формируются через `{% url %}`:

```django
{% url 'games_app:detail' game.id %}
```

Пространства имён приложений: `homepage`, `games_app`, `achievement`,
`progress_records`. Параметры маршрутов называются `game_id`,
`achievement_id`, `progress_id`.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/games.json`;
* `data/users.json`;
* `data/achievements.json`;
* `data/progress.json`.

При загрузке данные из JSON преобразуются в объекты `Game`, `User`,
`Achievement` и `Progress`. При сохранении объекты преобразуются обратно
в JSON. Для связи прогресса с игроком и достижением используются
идентификаторы `user_id` и `achievement_id`, для связи достижения с игрой –
идентификатор `game_id`.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за запуск
консольного приложения, отображение меню и пользовательские сценарии.

### `config/`

Пакет настроек Django-проекта:

* `settings.py` – настройки проекта и подключение приложений;
* `urls.py` – маршрутизация верхнего уровня;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу, общий каркас шаблонов
и статические файлы проекта:

* `views.py` – view-функция `index()` и обработчик `page_not_found()`;
* `urls.py` – маршрут главной страницы;
* `templates/homepage/index.html` – шаблон главной страницы;
* `templates/404.html` – шаблон кастомной страницы ошибки 404;
* `static/homepage/` – собственные статические файлы проекта
  (`css/style.css`, `js/main.js`, `img/logo.png`).

### `templates/` (корень проекта)

Шаблоны уровня проекта, общие для всего сайта:

* `base.html` – базовый шаблон;
* `includes/navigation.html` – включаемая навигация.

Каталог шаблонов уровня проекта подключён в `config/settings.py`
параметром `TEMPLATES["DIRS"] = [BASE_DIR / "templates"]`, а шаблоны
приложений находятся через `APP_DIRS`.

### `games_app/`

Django-приложение, отвечающее за игры:

* `views.py` – view-функции `games()` и `game_detail()`;
* `urls.py` – маршруты приложения (`app_name = "games_app"`);
* `templates/games_app/` – шаблоны списка и карточки игры, а также
  включаемая карточка `includes/game_card.html`;
* `models.py` – Django-модели (заполняется в следующих работах).

### `achievement/`

Django-приложение, отвечающее за достижения:

* `views.py` – view-функции `achievements()` и `achievement_detail()`;
* `urls.py` – маршруты приложения (`app_name = "achievement"`);
* `templates/achievement/` – шаблоны списка и карточки достижения, а также
  включаемая карточка `includes/achievement_card.html`;
* `models.py` – Django-модели (заполняется в следующих работах).

### `progress_records/`

Django-приложение, отвечающее за прогресс игроков:

* `views.py` – view-функции `progress_list()` и `progress_detail()`;
* `urls.py` – маршруты приложения (`app_name = "progress_records"`);
* `templates/progress_records/` – шаблоны списка и карточки прогресса,
  а также включаемый блок статуса `includes/progress_status.html`;
* `models.py` – Django-модели (заполняется в следующих работах).

Примечание. Имена Django-приложений (`games_app`, `achievement`,
`progress_records`) отличаются от одноимённых модулей ПР3 (`games.py`,
`achievements.py`, `progress.py`), чтобы не перекрывать их при импорте:
пакет приложения с тем же именем занял бы место модуля в `sys.path`, и
консольная версия и тесты перестали бы импортировать функции ПР3. Именно
поэтому приложение игр называется `games_app`, а не `games` – каталог
`games/` перекрыл бы модуль `games.py`.

### `models/`

Классы предметной области (пакет ПР3):

* `games.py` – класс `Game`;
* `achievements.py` – класс `Achievement`;
* `users.py` – класс `User`;
* `progress.py` – класс `Progress`.

### `games.py`, `achievements.py`, `users.py`, `progress.py`

Функции бизнес-логики ПР3: добавление и поиск игр, достижений и игроков,
запись и обновление прогресса, поиск прогресса по идентификатору
(`get_progress_by_id()`, добавлена в ПР5).

### `storage.py`

Загрузка и сохранение данных:

* JSON → объекты Python;

## Запуск приложения

Веб-версия (Django):

```text
python manage.py runserver
```

После запуска открыть в браузере адрес:

```text
http://127.0.0.1:8000/
```

Так как в проекте установлен `DEBUG = False`, обычный `runserver` не
раздаёт статические файлы (логотип, CSS, JavaScript). Чтобы увидеть
полный интерфейс в режиме разработки, запускайте сервер с флагом
`--insecure`:

```text
python manage.py runserver --insecure
```

Флаг `--insecure` заставляет сервер разработки отдавать статику даже при
`DEBUG = False`; при этом также работает кастомная страница ошибки 404.
Альтернатива — временно установить `DEBUG = True` в `config/settings.py`
(тогда статика раздаётся по умолчанию, но для несуществующих адресов
Django показывает отладочную страницу вместо кастомной 404).

Консольная версия (сохранена):

```text
python main.py
```

## Текущее состояние и план развития

Реализовано (после ПР6):

* Django-проект и четыре Django-приложения (`homepage`, `games_app`,
  `achievement`, `progress_records`);
* маршрутизация URL двух уровней, именованные маршруты и пространства
  имён приложений (`app_name`);
* Django Template Language: базовый шаблон `base.html`, наследование
  `extends`, блоки `block`, включаемые шаблоны `include`;
* передача данных из представлений в шаблоны через контекст;
* циклы `{% for %}` с веткой `{% empty %}` и условия `{% if %}`;
* фильтры шаблонов (`|length`, `|default`);
* ссылки через `{% url %}` вместо жёстко заданных адресов;
* отображение данных предметной области (игры, достижения, прогресс);
* кликабельные игры и достижения в списках с переходом на страницы деталей;
* кастомная страница ошибки 404 (`handler404` + `templates/404.html`,
  наследует `base.html`) с контекстной подсказкой о неверном идентификаторе;
* обработка несуществующих идентификаторов (передача `None` в шаблон и
  код статуса 404);
* собственные статические файлы проекта: CSS, логотип и JavaScript
  (`homepage/static/homepage/`);
* оформление Bootstrap 5.3 в сочетании с собственными стилями;
* сохранена консольная версия приложения (ПР3).

подключение относится к следующим практическим работам.
