# Game Achievement Tracker

Консольное приложение для каталога игр, достижений и прогресса игроков. В версии ПР3 словари и списки из ПР2 заменены объектной моделью, а JSON-файлы сохранены в прежнем формате.

## Возможности

- просмотр игр и количества достижений;
- добавление игр и достижений;
- поиск достижений по названию или ID;
- создание пользователей;
- просмотр списка всех игроков;
- добавление и обновление прогресса;
- расчет процента и статуса достижения;
- вывод карточки прогресса по имени или ID игрока;
- загрузка и сохранение объектных коллекций в JSON;
- запись событий приложения в `logs/app.log`.

Сортировка достижений по сложности удалена из приложения.

## Объектная модель

Пакет `models/` содержит четыре сущности:

- `Game` — игра каталога с атрибутами `id`, `title` и методом `__str__()`;
- `Achievement` — достижение с атрибутами `id`, `game`, `name`, `required_actions`, `is_secret`; методы `is_unlocked()`, `progress_percent()` и `__str__()`;
- `User` — игрок с атрибутами `id`, `username`; методы `from_data()` и `__str__()`;
- `Progress` — прогресс игрока по достижению со ссылками на `User` и `Achievement`, количеством действий и датой; методы `update()`, `percent()`, `status()` и `__str__()`.

Связи объектов:

```text
Progress -> User
Progress -> Achievement -> Game
```

Идентификаторы связей используются только на границе хранения. Внутри приложения `Progress` содержит реальные объекты пользователя и достижения, а `Achievement` — объект игры.

## Сценарии меню

1. Показать список игр и число достижений каждой игры.
2. Выбрать игру по ID и показать ее достижения.
3. Показать все достижения.
4. Добавить игру.
5. Добавить достижение к выбранной игре.
6. Найти достижение по названию или ID. Числовой ввод ищет точное совпадение по ID, текстовый ввод — достижения по части названия без учета регистра.
7. Показать всех игроков.
8. Зафиксировать прогресс: игрок выбирается по имени, новый игрок создается автоматически.
9. Показать карточку прогресса: игрок выбирается по имени или числовому ID, затем выбирается достижение.
0. Сохранить все коллекции в JSON и завершить работу.

Некорректный числовой и календарный ввод обрабатывается функциями из `utils.py`. Несуществующие игры, достижения и игроки не приводят к созданию некорректных связей.

## Структура проекта

- `main.py` — консольное меню и пользовательские сценарии.
- `models/games.py` — класс `Game`.
- `models/achievements.py` — класс `Achievement`.
- `models/users.py` — класс `User`.
- `models/progress.py` — класс `Progress`.
- `models/__init__.py` — публичный экспорт моделей.
- `games.py` — добавление и поиск игр.
- `achievements.py` — добавление, поиск и получение достижений по игре или ID.
- `users.py` — добавление, поиск по имени или ID и вывод игроков.
- `progress.py` — создание, поиск и обновление прогресса.
- `storage.py` — преобразование JSON в объекты и обратно.
- `utils.py` — безопасный ввод чисел и дат.
- `data/` — JSON-файлы приложения.
- `logs/` — файл выполнения приложения `app.log`.
- `tests/` — параметризованные тесты объектной модели и бизнес-логики.

## Формат JSON

Формат данных совместим с ПР2. Файлы хранят простые записи и идентификаторы связей:

- `data/games.json`: `id`, `title`;
- `data/users.json`: `id`, `username`;
- `data/achievements.json`: `id`, `game_id`, `name`, `required_actions`, `is_secret`;
- `data/progress.json`: `id`, `user_id`, `achievement_id`, `completed_actions`, `record_date`.

Пример записи прогресса:

```json
{
  "id": 1,
  "user_id": 1,
  "achievement_id": 1,
  "completed_actions": 10,
  "record_date": "2026-09-15"
}
```

При загрузке `storage.py` связывает идентификаторы с объектами `User`, `Achievement` и `Game`. При сохранении объектные ссылки снова преобразуются в идентификаторы. Если связанный объект отсутствует, запись пропускается.

## Требования и установка

- Python 3.10 или новее;
- `pytest`;
- `flake8`.

```powershell
pip install -r requirements.txt
```

## Запуск приложения

Из каталога `project`:

```powershell
python main.py
```

Пути к данным относительные, поэтому приложение нужно запускать из корня проекта.

## Тестирование

```powershell
pytest -v
```

Текущий результат: `17 passed`.

Тесты проверяют создание объектов, атрибуты, строковые представления, восстановление `User` через `from_data()`, разблокировку достижений, расчет процента, поиск игр/игроков/достижений, вывод списка игроков, обновление прогресса и связи `Progress` с `User` и `Achievement`.

Тесты разделены маркировками:

```powershell
pytest -m smoke -v
pytest -m unit -v
```

`smoke` содержит быстрые базовые проверки создания и связывания объектов, `unit` — модульные проверки поиска, обновления и бизнес-логики. Параметризованные тесты проверяют несколько вариантов входных данных в одном сценарии.

## Логирование

Приложение использует стандартный модуль `logging`. При запуске создается или дополняется файл `logs/app.log`. В него записываются запуск приложения, успешное сохранение данных и неизвестные пункты меню. Журнал не заменяет JSON-файлы хранения.
