Шаблон Django – HTML-документ, содержащий специальные конструкции

языка шаблонов Django. Шаблон отвечает за представление данных. Например:

<h1>{{ room.name }}</h1>

<p>Вместимость: {{ room.capacity }}</p>

Здесь {{ room.name }} означает получение значения name объекта room.

Сам объект передаётся из view-функции. Например:

def room_detail(request, room_id):

rooms_list = load_rooms()

room = find_room_by_id(rooms_list, room_id)



context = {

"room": room,

}



return render(request, "rooms/room_detail.html", context) Таким образом, Python-код не формирует HTML-строку. Он подготавливает данные для страницы.

3.3. Функция render()

Для формирования ответа на основе шаблона используется функция render(): from django.shortcuts import render

Общий вид:

return render(request, "имя_шаблона.html", context) где:

• request – текущий HTTP-запрос;

• второй аргумент – путь к шаблону;

• context – словарь данных, передаваемых шаблону.

Например:

def rooms(request):

rooms_list = load_rooms()



context = {

"rooms": rooms_list,

}



return render(request, "rooms/room_list.html", context) В шаблоне:

{% for room in rooms %}

<h2>{{ room.name }}</h2>

<p>Вместимость: {{ room.capacity }}</p>

{% endfor %}

3.4. Контекст аблона


Контекст – словарь, содержащий данные, которые должны быть доступны в

шаблоне. Например:

context = {

"rooms": rooms_list,

"page_title": "Помещения Roomly",

}

8





В шаблоне эти значения доступны по соответствующим именам:

<h1>{{ page_title }}</h1>



{% for room in rooms %}

<p>{{ room.name }}</p>

{% endfor %}

Важно соблюдать соответствие имён. Если во view используется: context = {

"rooms": rooms_list,

}

то в шаблоне необходимо обращаться к:

{{ rooms }}

а не к:

{{ rooms_list }}

если такая переменная отдельно в контекст не передавалась.

3.5. Выражения {{ ... }}

Для вывода значения в шаблоне используются двойные фигурные скобки:

{{ variable }}

Например:

{{ room.name }}

{{ room.capacity }}

{{ booking.status }}

Можно обращаться к атрибутам объектов, например {{ room.name }}, а

также к элементам структур данных. В ПР6 необходимо использовать шаблоны для

отображения объектов предметной области: Room, User, Booking.

При этом предметная логика продолжает находиться в Python-коде. Шаблон не

должен превращаться в место реализации бизнес-логики.





3.6. Условия в аблонах


Для условного отображения используется конструкция:


{% if условие %}

...

{% else %}

...

{% endif %}

9





Например:

{% if booking.is_cancelled %}

<p>Бронирование отменено</p>

{% else %}

<p>Бронирование активно</p>

{% endif %}

В Roomly условные конструкции необходимо использовать для отображения

Например:

• наличие или отсутствие помещений;

• наличие данных о пользователе;

• доступность помещения.





3.7. Циклы в аблонах


Для перебора коллекции используется:


{% for объект in коллекция %}

...

{% endfor %}

Например:

{% for room in rooms %}

<article>

<h2>{{ room.name }}</h2>

<p>Вместимость: {{ room.capacity }}</p>

</article>

{% endfor %}

Для пустой коллекции можно использовать empty:

{% for room in rooms %}

<article>

<h2>{{ room.name }}</h2>

</article>

{% empty %}

<p>Помещения не найдены.</p>

{% endfor %}

Это позволяет обрабатывать ситуацию, когда данные отсутствуют, непосредственно в шаблоне.

3.8. Наследование аблонов

Если каждая HTML-страница содержит одинаковые элементы:

• DOCTYPE;

• <head>;

• подключение CSS;

• меню;

• контейнер страницы;

• подвал

Копировать этот код в каждый файл не следует. Для общей структуры используется базовый шаблон. Например:

<!DOCTYPE html>

<html lang="ru">

<head>

<meta charset="UTF-8">

<title>{% block title %}Roomly{% endblock %}</title>

</head>

<body>



<nav>

...

</nav>



<main>

{% block content %}

{% endblock %}

</main>



</body>

</html>

Другой шаблон наследует эту структуру:

{% extends "base.html" %}



{% block title %}

Помещения

{% endblock %}



{% block content %}

<h1>Помещения</h1>

{% endblock %}

Такой подход позволяет изменять общую структуру сайта в одном месте.

11





3.9. Подключение частей аблона чере includ Повторяющиеся элементы страницы можно вынести в отдельные шаблоны.

Например, карточка помещения:

<article class="room-card">

<h2>{{ room.name }}</h2>

<p>Вместимость: {{ room.capacity }}</p>

</article>

Сохранить её можно как отдельный шаблон:

rooms/

└── templates/

└── rooms/

└── includes/

└── room_card.html

В основном шаблоне:

{% for room in rooms %}

{% include "rooms/includes/room_card.html" %}

{% endfor %}

Это позволяет избежать дублирования HTML-кода.





3.10. Именованные и пространства имён


В ПР5 адреса страниц указывались в HTML непосредственно:

<a href="/rooms/">Помещения</a>

В ПР6 необходимо перейти к именованным маршрутам. В rooms/urls.py: app_name = "rooms"



urlpatterns = [

path("", views.rooms, name="list"),

path("<int:room_id>/", views.room_detail, name="detail"),

]

Теперь в шаблоне используется:

<a href="{% url 'rooms:list' %}">

Помещения

</a>

Для конкретного помещения:

<a href="{% url 'rooms:detail' room.id %}"> Подробнее

</a>

Преимущество такого подхода заключается в том, что HTML не зависит непосредственно от конкретного URL. Если маршрут изменится:

12





path("all/", views.rooms, name="list") ссылка:

{% url 'rooms:list' %}

останется прежней.





3.11. Фильтры аблонов


Фильтры позволяют изменять представление значения непосредственно в шаблоне. Например:

{{ rooms|length }}

выводит количество помещений.

Для значения, которое может отсутствовать, можно использовать:

{{ room.name|default:"Без названия" }}

Для даты:

{{ booking.booking_date|date:"d.m.Y" }}

Фильтры следует использовать для представления данных, а не для переноса бизнес-логики из Python в шаблон.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django.

Основные страницы:

- главная страница;

- список помещений;

- информация об отдельном помещении;

- список бронирований;

- информация об отдельном бронировании.

Для формирования страниц используются Django-шаблоны.

Генерация HTML непосредственно в Python-коде веб-представлений не используется. Функция page() больше не

используется веб-представлениями.

Представления подготавливают данные и передают их в шаблоны через контекст.

## 6. Django Template Language

Шаблоны используют возможности Django Template Language.

### Базовый шаблон

Общий шаблон страниц:

templates/base.html

Он содержит общую HTML-структуру страницы, подключение стилей и JavaScript, навигацию и блоки для содержимого

отдельных страниц.

Дочерние шаблоны используют наследование:

{% extends "base.html" %}

Содержимое отдельных страниц размещается в блоке:

{% block content %}

{% endblock %}

Заголовок страницы задаётся через блок:

{% block title %}

{% endblock %}

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны.

Для помещений используется:

rooms/includes/room_card.html

Для отображения состояния бронирования:

bookings/includes/booking_status.html

Подключение выполняется с помощью:

{% include "rooms/includes/room_card.html" %}

или:

{% include "bookings/includes/booking_status.html" %}

### Контекст

Представления передают данные в шаблоны через словарь контекста.

Например, для списка помещений:

context = {

"rooms": rooms_list,

}

В шаблоне данные доступны по имени переменной:

{% for room in rooms %}

Для страницы отдельного помещения используется переменная:

{{ room }}

Аналогичный подход используется для бронирований.

### Циклы и условия

Для формирования списков используются циклы:

{% for room in rooms %}

При отсутствии элементов используется:

{% empty %}

Условия используются для отображения различного содержимого страницы и состояния бронирования:

{% if booking.is_cancelled %}

## 7. Фильтры шаблонов

В шаблонах используются стандартные фильтры Django Template Language.

Например, количество помещений:

{{ rooms|length }}

Для отображения значения по умолчанию:

{{ room.name|default:"Без названия" }}

Фильтры используются для представления данных и не содержат бизнес-логику приложения.

Дата бронирования на текущем этапе хранится как строковое значение и выводится без преобразования средствами

шаблона.
